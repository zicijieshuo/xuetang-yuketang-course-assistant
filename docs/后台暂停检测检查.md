# 后台暂停检测检查（2026-10-08）

此文记录初步可行性检查；随后已按用户要求实现可选后台播放模式，最终验证见验证记录。

## 前端证据

已下载的公开播放器源码 `research/web-27437.js` 中，`winTriggerHidden` 注册 `visibilitychange`，读取 document.hidden，另处理 blur、focusout、pagehide 等事件并触发暂停。isAbleOcclusion 配置会影响该分支，不能仅凭库内代码确定当前课程的所有处理路径。

课程包装源码 `research/web-3836.js` 将 isAntiBrushing 传入播放器；`research/web-79807.js` 根据平台返回的 anti_brushing 配置设置该值。未调用或修改这些接口，也未改动学习记录。

## 独立本地窗口测试

使用临时独立 Edge 配置及本地空白测试页面，通过 CDP 的 Emulation.setFocusEmulationEnabled 比较状态：

| 条件 | visibilityState | document.hidden | document.hasFocus() |
| --- | --- | --- | --- |
| 最小化，未开启模拟 | hidden | true | false |
| 最小化，开启焦点模拟 | visible | false | true |
| 最小化，关闭焦点模拟 | hidden | true | false |

结果表明本机 Edge 可以在浏览器层模拟页面焦点与可见性。它能影响前端检测输入，但未验证真实课程的媒体持续播放、进度上报或服务端完成判定。

原版助手另外读取真实窗口最小化状态，并进入 WAIT_VISIBLE。新版用户开启后台模式后跳过物理最小化等待，同时保持用户暂停和停止语义。

修改页面可见性属性或事件监听也是理论路径，但刷新、iframe、其他事件处理及版本更新会影响可靠性。浏览器关闭节流参数则不能直接改变 document.hidden，不能单独解决站点主动暂停。

参考：MDN Page Visibility API，https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API 。
